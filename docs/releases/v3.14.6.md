# v3.14.6 Release Notes

**Release Date:** 2026-09-29

## Highlights

Agentic QE 3.14.6 fixes an `aqe audit verify` crash on stores that have no
audit chain yet, and adds `aqe audit repair` so stores forked by concurrent
writers before 3.14.5 can pass verification again. Repeat `aqe init --auto`
runs now leave an unchanged project untouched. GOAP planning works from the
live fleet state and no longer labels defaults as real data. Secrets are
redacted from AQE's logs, and keyword matches now improve pattern search.
Thanks to [@pacphi](https://github.com/pacphi) and
[@nagoodman](https://github.com/nagoodman) for the reports and re-tests, and to
[@rudycelekli](https://github.com/rudycelekli) for the fleet and GOAP plan
fixes.

## Audit chain

- `aqe audit verify --chain audit` no longer crashes with `SQLITE_READONLY`
  on a fresh or older store. It keeps checking past accidental forks and
  reports them separately from tampering.
- `aqe audit repair --chain audit [--dry-run]` makes a store forked before
  3.14.5 pass verification again:
  - it refuses if anything was tampered with;
  - it backs up the database first;
  - it adds one signed entry and never edits or deletes existing rows.
- A store whose live chain was deleted while archived rows remain is reported
  as tampered.

## Setup that converges

- A second `aqe init --auto` on an unchanged project leaves every generated
  file byte-for-byte identical and creates no `settings.json.backup`.
- Fresh and repeat runs now produce the same settings: all 13 domains, and
  pattern promotion at 3 successes / 0.7 success rate, which the learning
  runtime has always enforced.

## GOAP planning

- World state comes from the live fleet (and from a coverage report when one
  exists). Values that can't be measured are `null` and labelled `estimated`.
- Planning for goals such as `achieve-90-percent-coverage` works again.
  `maxSteps` is supported, and a returned plan can be dry-run executed.
- A step whose domain call returns an error now fails instead of reporting
  success.
- `goap_status {type:"plans"}` lists saved plans, and a repeat `fleet_init`
  reports the settings actually in effect.

## Logs and search

- Secrets are redacted from AQE's structured logs and logged errors: API keys,
  tokens, credentials in URLs, JWTs, PEM keys, and values under sensitive keys.
  Command output such as `aqe memory get` is unchanged.
- Keyword matches now contribute to pattern search. A keyword-only hit is
  weighted by how many query terms it matches, so a single common word can't
  outrank a strong semantic match.
- `qe_coherence_consensus` validates the vote shape and states the real tally.

## Upgrade notes

- **Audit chain:** if `aqe audit verify --chain audit` reported BROKEN on a
  store used by several AQE processes before 3.14.5, run
  `aqe audit repair --chain audit --dry-run`, then
  `aqe audit repair --chain audit`. Stores changed by a `brain import` from
  before 3.14.5 contain an unlinked audit row. That row can't be told apart
  from tampering, so those stores stay BROKEN and need a restore from a backup
  taken before the import.
- **Settings:** the first `aqe init --auto` after upgrading may update
  `settings.json` once, to the canonical domain list and promotion thresholds.
  Later runs don't change it.
- **MCP:** `goap_plan` now rejects unknown `constraints` keys, and
  `qe_coherence_consensus` rejects votes without a `verdict`.

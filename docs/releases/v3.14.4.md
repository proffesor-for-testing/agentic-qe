# v3.14.4 Release Notes

**Release Date:** 2026-09-27

## Highlights

Agentic QE 3.14.4 moves to the current AI model generation (Claude Sonnet 5
and Opus 5.5, GPT-6, `qwen3-coder:30b` locally) and fixes requests that were
failing outright on the newest Claude and GPT models. It closes a shell
injection and a git option injection reachable from MCP tool arguments, makes
task, workflow, and backup results reflect what actually happened, and stops
running `aqe` from a subfolder from creating stray learning stores. Most of the
fixes in this release were contributed by [@rudycelekli](https://github.com/rudycelekli).

## Models

- Routing tiers now use Claude Haiku 4.5, Sonnet 5 (tiers 2–3, cheaper than
  Sonnet 4.6), and Opus 5.5 (tier 4 and the advisor). Opus 5, Opus 4.8 and the
  Fable family are registered and priced for opt-in use.
- Native Claude requests no longer fail on Opus 4.7 and the Claude 5 models,
  which reject `temperature` and expect effort as `output_config.effort`.
  GPT-6 requests send `max_completion_tokens`. Opus/Fable-class models again
  honor `QE_EFFORT_LEVEL` and `config/fleet-defaults.yaml`.
- OpenAI defaults are `gpt-6-sol` / `gpt-6-luna`; Azure deployments running
  GPT-5/6 should set `model` explicitly. The local free-tier and judge default
  is `qwen3-coder:30b` (pull it with `ollama pull qwen3-coder:30b`).
- Retired Claude 3.x, Sonnet 4 and Opus 4 defaults are gone. Budgets and cost
  tracking now price every routable model instead of treating unknown models as
  free.
- Security agents stay on Sonnet 4.6 for every Opus/Fable-class model until
  `AQE_CYBER_VERIFIED=true`, including fallback paths and the Claude Code
  `opus` alias.

## Security

- File paths passed to `model_route` / `task_orchestrate` can no longer run
  shell commands through git history lookups.
- Git refs that look like options (for example `--output=<path>`) are rejected
  by `qe_tests_schedule`, `aqe test schedule --git-ref`, and
  `aqe code index --git-since`.
- All open Dependabot alerts in the vendored Ruflo tree are patched.

## Honest outcomes

- `aqe fleet run` and `aqe task submit --wait` exit 1 when work fails or never
  ran. **Behavior change:** `fleet run test` / `analyze` currently fail because
  `--target` is not yet mapped to a task payload, and `scan` waits for its 60 s
  deadline; before this release they reported success without doing the work.
- MCP `task_submit` reports the task's real state, and failed MCP tool calls
  are marked `isError` with the original error logged on the server.
- Cancelled tasks stay cancelled when a late result arrives, ambiguous
  protocol timeouts are recorded as `unknown` instead of replayed, and aborting
  or Ctrl+C stops the whole Vitest process tree.
- Incomplete Vitest execution evidence is rejected, and Vitest tests are
  counted from JSON discovery.
- `aqe ci run` evaluates measured evidence in its quality-gate phase and exits
  1 when an enforced gate did not run (use `--no-quality-gate` for advisory
  runs).

## Workflows

- Approval-gated steps wait for approval before running the action, and
  unanswered gates expire as failures. Approve or reject through the new
  `pipeline_approve` / `pipeline_reject` MCP tools.
- Parallel workflow steps compose their outputs atomically, so concurrent
  steps can no longer overwrite each other.
- Cached MCP reads are invalidated after state-changing tools.

## Learning data and storage

- Learning backups are consistent point-in-time snapshots that keep committed
  WAL data, and restore takes a verified safety copy first.
- Healthy RVF stores behind a stale lock are preserved instead of quarantined.
- `aqe brain import` no longer aborts on natural-key pattern conflicts, and
  `--dry-run` previews the real merge result.
- Configured database filenames are honored, explicit `:memory:` databases
  stay in memory, the project-root lookup is scoped to the requested
  directory, and re-running `aqe init` after `--no-database` restores
  persistent settings.

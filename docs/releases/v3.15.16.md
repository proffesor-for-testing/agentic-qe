# v3.15.16 Release Notes

**Release Date:** 2026-10-27

## Highlights

A locked `.agentic-qe/memory.db` no longer freezes the MCP server: database
writes from tool calls and background workers wait for the lock without
blocking other calls. Accessibility checks report what axe-core actually
measured, or say "not measured", instead of made-up values. Test runs in a
monorepo use each package's own runner config. Code search covers every
indexed file and says when part of the result is a text match. The learning
system no longer waits on a silent embedder host and only compares
experiences embedded by the same model.

## Fixed

- **A locked memory.db no longer stalls the MCP server** ([#1263], [#1274],
  [#1275], [#1284], [#1290]): while another process held the write lock,
  each blocked write froze the server for up to 5 seconds, so every tool
  call, even `fleet_status`, could wait 10–15 seconds. Writes from tool
  calls, the session cache, learning, the spend ledger, planning and the
  background workers (heartbeat, consolidation, SONA saves) now go through
  one queue that waits for the lock without blocking. Under a held lock,
  `fleet_status` now answers in about 0.2 s instead of 3.5 s. Callers get
  the same result as before: success, or a busy error after the usual 5 s.
  Some startup schema changes and separate connections are still tracked
  in [#1283].
- **Accessibility results are measured, not made up** ([#1228], [#1271],
  [#1270], [#1277]): contrast failures report the colours and ratios
  axe-core measured (they used to report black on white at ratio 1.0), and
  axe's `serious` and `minor` impacts are no longer reported as `moderate`.
  PII, layout-shift and keyboard focus checks that did not run say "not
  measured" instead of reporting a clean result. `aqe task submit --wait`
  prints the task's result, and `--output <file>` saves it.
- **Monorepo test runs use each package's config** ([#1247], [#1273]):
  `test_execute_parallel` and `aqe test execute` run each test file from the
  nearest directory with its own Vitest or Jest config, so package setup
  files and aliases load. `test_execute_parallel` takes an optional
  `projectRoot`, which must be inside the project.
- **Code search covers every indexed file** ([#1230], [#1231], [#1278],
  [#1279], [#1286], [#1287]): indexing no longer stops embedding after 100
  files, and a search reports `partial-vector` mode with coverage when some
  files only have text. Text matching now requires the query word to appear
  inside a word of the file, so a short word in the file no longer matches
  a longer query word. How
  tied text matches are ordered is tracked in [#1287].
- **The learning system no longer hangs on a silent embedder host**
  ([#1216], [#1280], [#1285], [#1289]): a request that times out opens the
  circuit breaker at once, the recovery probe runs in the background, and
  each request removes its socket listeners when it finishes.
- **Experiences are compared only within one embedding space** ([#1217],
  [#1280], [#1281], [#1288]): experience search and consolidation only use
  vectors from the active embedding model, so experiences from another model
  are no longer merged as near-duplicates. Older rows are marked
  with their space only when the current model reproduces the stored vector;
  stored vectors are never rewritten. A client that accepts a changed model
  fingerprint after the breaker recovers is tracked in [#1282].

## Changed

- **CI:** the coverage run is split into 3 parallel shards and merged into
  the same report, so Coverage Analysis no longer hits its time limit
  ([#1201], [#1276]).

# v3.15.17 Release Notes

**Release Date:** 2026-10-28

## Highlights

Python projects can run their pytest suites through AQE, and those runs now
count as measured outcomes. VS Code Copilot picks up the current AQE tools
after an upgrade instead of keeping a stale cached tool list. The learning
system keeps the same embedding space when the same model restarts, and
refuses a different model behind the same endpoint. Semantic code search
uses an installed Ollama MiniLM model, and text matches are ranked by how
closely they match.

## Added

- **pytest support** ([#1248], [#1303]): `aqe test execute` and
  `test_execute_parallel` run `.py` test files with
  `python -m pytest --junitxml` and report passed, failed and skipped tests
  by name. Python projects are detected from `pytest.ini`, `pyproject.toml`,
  `setup.cfg`, `tox.ini` or `conftest.py`. Set `AQE_PYTHON` to choose the
  interpreter. A run that does not finish (pytest not installed, no tests
  collected, a collection error) is reported as an error, never as a pass,
  and Python files are never sent to Vitest. Follow-ups, including recording
  outcomes from the CLI and pytest coverage, are tracked in [#1304].

## Fixed

- **VS Code Copilot no longer keeps stale AQE tools after an upgrade**
  ([#1269], [#1293]): VS Code caches each MCP server's tools and refreshes
  them only when the server's launch settings change, so after an upgrade
  Copilot could keep rejecting an old tool schema. `aqe init` now writes
  the installed AQE version into the server's `env` in `.vscode/mcp.json`
  (still launching `agentic-qe@latest`), so re-running init after an
  upgrade makes VS Code reload the tools. Re-init only updates AQE's own
  entry and leaves a file with comments untouched. If Copilot still shows
  the error, run "MCP: Reset Cached Tools". A check in the test suite now
  fails the build if any tool schema has an array without `items`.
- **A different embedding model behind the same endpoint is refused**
  ([#1282], [#1295]): after the circuit breaker recovered, the embedder
  client accepted whatever model now answered. It now refuses a changed
  model with a clear error, so vectors from two models are never mixed.
  The same model with tiny numeric differences is still accepted.
- **The same model keeps its embedding space after a restart** ([#1298],
  [#1301]): the embedding space id came from an exact fingerprint, so tiny
  float differences after a restart started a new space and hid earlier
  experiences. Known spaces are now recorded and matched by similarity, and
  `backfill-embeddings` no longer rewrites stored vectors after such a
  restart. Remaining edge cases are tracked in [#1302].
- **Semantic code search uses an installed Ollama MiniLM model** ([#1229],
  [#1297]): `all-minilm` (the L6 model, under any tag Ollama lists) is
  recognised and requested by its installed name, so search no longer drops
  to text-only. The error says whether the model is missing, Ollama is not
  reachable, or the request failed. `AQE_OLLAMA_EMBEDDING_MODEL` selects
  another Ollama model, which gets its own embedding space.
- **Ranking among text matches** ([#1287], [#1299]): when several files
  match the query words equally, an exact identifier match comes first,
  then words next to each other, whole words before partial ones, and more
  occurrences before fewer. Scores are unchanged.
- **Test runs pick each package's runner** ([#1272], [#1300]): a Jest
  package in a monorepo is run with Jest even when the default is Vitest,
  the flaky detector runs from the package directory, and
  `aqe test execute --project-root <dir>` is available on the CLI.
  `--framework` is only passed on when you set it.

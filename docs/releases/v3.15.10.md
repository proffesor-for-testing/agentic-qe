# v3.15.10 Release Notes

**Release Date:** 2026-10-19

## Highlights

Files named in a request are now read only when they are inside your
project, and secrets in test failures are redacted everywhere AQE returns
or stores them. Advertised `aqe fleet run` and `task_orchestrate` commands
run real handlers and judge what they returned. A dream can no longer lose
an acknowledged memory write, git and other slow tools no longer freeze
the MCP server, and the learning success rate counts measured outcomes
only. Every change was reviewed adversarially before merge.

## Security

- **Paths in a request are read only inside the project** ([#1126],
  [#1162], [#1125], [#1144]): before, a caller could ask AQE over MCP to
  read any file on the machine, and one request for `/dev/zero` crashed the
  server. Every handler that reads a file or folder named in a request
  (`generate-tests`, `execute-tests`, `predict-defects`, `sast-scan`,
  `security_scan_comprehensive`, `coverage_analyze_sublinear`,
  `code_index`, `contract_validate` and others) now applies one shared
  check, on every entry point: MCP tools, `task_submit`,
  `task_orchestrate` and `aqe task submit`.
  - The real location, with every symlink followed, must be inside the
    project root. A symlink that points out, and `src/link/../x` when
    `src/link` points out, are refused.
  - Only regular files are read, at most 2 MB each where a file is read
    whole. Devices, FIFOs and (except where a folder is expected)
    directories are refused before anything is opened.
  - A path outside the project is refused without touching the
    filesystem, so the error does not reveal whether the file exists.
  - The refusal is a caller error: it is not retried and does not trip the
    domain circuit breaker.
- **Secrets in test failures are redacted** ([#1122], [#1139]): a
  connection string, AWS key or bearer token in a failing test's message
  used to come back verbatim from `test_execute_parallel` and
  `aqe test execute`, and was saved under `.agentic-qe/results/`, in
  session logs and in `memory.db` (test runs, experiences, retry and flaky
  history). All of these copies are now redacted, before any length cap,
  so a secret cut in half cannot survive. The `error` of every MCP domain
  tool is redacted as a backstop.
- **Lookups keyed by caller data read own properties only** ([#1136],
  [#1156], [#1118], [#1132]):
  - `${constructor}` or `{{toString}}` in a pipeline YAML, browser
    workflow, workflow condition or cross-phase hook no longer expands to
    native function source. It stays literal.
  - JSON Pointer and JSON Patch paths such as `/__proto__/x` in the A2UI
    and AG-UI adapters can no longer write to `Object.prototype`.
  - Required-property checks in contract, enterprise-integration and MCP
    schema validation no longer count an inherited `constructor` as
    present.
  - Name tables (agent names, gate rules, routing categories,
    `aqe ruvector flags --profile`, faker paths and recovery playbook
    services) no longer match inherited members. Thanks to @rudycelekli
    for the recovery playbook fix.
- **DAST scans fail when the target cannot be reached** ([#1092]): an
  initial 401/403 now fails with `DAST_AUTHENTICATION_FAILED` and a 5xx
  with `DAST_TARGET_UNAVAILABLE`. Before, an unreachable target could
  produce a completed scan. Failed follow-up probes fail the scan, and a
  failed scan is not stored as completed. Thanks to @rudycelekli.

## Fixed

- **Dreams no longer put memory writes at risk** ([#1060], [#1160]): a
  dream does its work in memory and writes its results in one short
  transaction at the end. An acknowledged `memory_store` made during a
  dream is kept however the dream ends: it finishes, is cancelled, the
  engine closes, stdin closes or the process is killed. `cancelDream()`,
  `close()` and shutdown stop a dream at once and record it `interrupted`.
  A second dream request while one runs is refused instead of interrupting
  it. A cycle left `running` by a dead process is marked `interrupted`
  (never deleted) after 11 minutes. Thanks to @pacphi for the report and
  reproduction in [#1060].
- **Slow child processes no longer freeze the MCP server** ([#1115],
  [#1148]): git (defect prediction, task routing, the quality daemon's
  watcher), `cloc`/`tokei` and test-runner listings for `code_index`, and
  `npx agent-browser` for the browser tools now run asynchronously with
  timeouts. A timeout stops the child's whole process group, so nothing is
  left running. With a git that took 1 s per call, `fleet_status` used to
  wait up to 12 s; now it answers in well under a second.
- **Learning's success rate counts measured outcomes only** ([#1129],
  [#1121], [#1142]): `aqe learning stats` said 100% after test runs with a
  failing test. Now only a test run is a measured outcome (it passes when
  every test passed, and both results are recorded), and the rate counts
  runs, not rows. Completed calls, errors, hook-reported `--success` and
  session-consolidation aggregates count as uses, not verdicts. Existing
  rows are classified on read; nothing is deleted or rewritten. The
  learning dashboard no longer shows an invented `0.5` learning rate or a
  `100%` transfer rate, and patterns stored before 3.15.9 are kept but left
  out of stats.
- **Learning consolidation cannot lose patterns** ([#1106], [#1143]): a
  merge now reads back every archived source and the merged pattern before
  removing the sources. If any step fails, nothing is merged. A failed
  domain or merge is reported as `status: 'partial'` with an `errors` list
  instead of success. A dry run now predicts the same trims as a real run,
  and a key scan that never ends stops with an error.
- **Advertised commands run real handlers** ([#1125], [#1144]):
  `aqe fleet run scan` runs a SAST scan on the target's JS/TS files,
  `analyze` uses the coverage report that already exists for the target,
  and `test` generates tests for the target's sources. `task_orchestrate`
  routes `scan-security` to `sast-scan` and `assess-quality` to
  `analyze-quality` when you pass `filePaths`. Requests that lack the
  input a handler needs are refused with the tool to use instead; nothing
  is estimated. `task_submit` with `sast-scan` now accepts plain path
  strings.
- **Index tasks run, or are refused up front** ([#1086], [#1134],
  [#1159]): an inferred `index-code` task now runs the code-intelligence
  handler with the paths it was given. Thanks to @rudycelekli.
- **Queen slots are always handed on** ([#1127], [#1138], [#1140],
  [#1152]): a slot freed while the queue drains goes to the next queued
  task. Work stealing moves a task only to a domain that can run it and
  never exceeds `maxConcurrentTasks`. A failure at dispatch publishes
  `QueenTaskFailed` once and frees its slot once; a plugin that throws no
  longer leaves its task `running`.
- **Retries rerun tests inside `describe` blocks** ([#1141], [#1151]): the
  retry filter only ever matched top-level tests. It now matches the full
  name for Vitest, Jest and Mocha. A retry that selects no test is
  reported as `unmatched` instead of counting as an attempt.
- **Retry results are reported** ([#1130], [#1163]):
  `test_execute_parallel` returns `retryStats` (retries run, now passing,
  still failing, per test) and `aqe test execute` prints a `Retries:` line.
- **`fleet_status` stays healthy during a test run** ([#1130], [#1163]):
  the agent spawned for one task no longer marks the fleet `degraded`
  while it runs or after it finishes. Real topology problems and failed
  agents still degrade the status. `fleet_health({ detailed: true })`
  shows the raw MinCut reading.
- **Chaos wording is not run as tests** ([#1130], [#1163]): "Run chaos
  resilience testing with fault injection" now gets chaos guidance from
  `task_orchestrate` instead of being submitted as `execute-tests`.
- **Dream archive and worker status are reported truthfully** ([#1116],
  [#1155]): a stale insight with a NULL id no longer makes every retention
  sweep fail. The generated `start-daemon.cjs` honours
  `AQE_WORKERS_ENABLED` (environment or Claude settings files) and says
  "started" only when the server is still running. MCP startup reports
  workers as `starting` until they have started.
- **Concurrent startups no longer fail with "database is locked" during a
  schema migration** ([#1116], [#1155]): a migration takes the write lock
  up front and waits for it.
- **Defect predictions reach the background worker** ([#1088]): public
  predictions are recorded in the shape the worker reads, history is
  bounded to the newest 32 runs, and the newest result is no longer hidden
  behind an old scan cap. Static scores are labelled as estimates. Thanks
  to @rudycelekli.

## Changed

- **`task_orchestrate` and fleet responses:** `type` is now the handler
  type that actually ran (for example `sast-scan`). The type inferred from
  the description moves to the new field `inferredType`. Clients that read
  `type` as the inferred type should read `inferredType`.
- **`aqe fleet run` shows results and a verdict.** It prints the findings,
  coverage or generated tests, and exits 1 with `Verdict: FAILED (…)` on a
  critical or high finding, incomplete scan evidence, a failed quality
  gate, coverage below 80% or an unreadable result. The count line now
  says `Completed: N` instead of `Successful: N`.
- **Payload paths are confined to the project root.** After `aqe init` in
  a monorepo package, a sibling package such as `../b/tests/x.test.ts` is
  refused. Set `AQE_PROJECT_ROOT=<repo root>` to let packages reach each
  other.
- **Interpolation no longer resolves inherited values.** `${constructor}`,
  `${toString}` and similar placeholders stay literal unless you define
  them.
- **`enableBranching` is a deprecated no-op.** The option is still
  accepted and logs a warning. `RVCOWBranchManager` is deprecated.
- **Index tasks without `paths` are refused at submit.** `task_submit` and
  `aqe task submit` with `index` or `index-code` need a non-empty `paths`
  list, and `task_orchestrate` needs `filePaths`. Use `code_index` or
  `aqe code index` to index a directory.
- **`task_orchestrate` refuses `optimize-learning` from free text**,
  because it overwrites the stored learned strategies. Use `task_submit`
  with type `optimize-strategies`. `run-chaos`, `validate-contracts`,
  `validate-requirements` and `test-accessibility` are refused with the
  tool to use instead.
- **Schema v14.** The `dream_insights_archive` table moves into the
  versioned schema with an additive, idempotent migration. 3.15.8 and
  3.15.9 still open a migrated database.
- **Learning success rates count measured outcomes only.** Projects that
  only have hook-reported outcomes now show "insufficient evidence"
  instead of 100%. `aqe learning stats --json` reports `measuredOutcomes`
  and `unmeasuredOutcomes`, and `patternSuccessRate` can be `null`.
- **Git timeouts are reported as unavailable, never as 0.** A prediction
  whose git history timed out carries a `warnings` entry, and its metrics
  are not cached.

## Known issues

- `task_orchestrate` still fails on an install without an embedder (the
  optional `@huggingface/transformers` package or `AQE_EMBEDDER_ENDPOINT`),
  so its new routing is only reachable with one configured ([#1022]).
- Payload path checks and the read that follows are not atomic, so a path
  swapped between them is not caught yet ([#1161]).
- Some direct `map[userKey]` lookups on plain objects remain to be audited
  ([#1157]).
- `aqe fleet run analyze` and `aqe coverage` can pass from a report that
  covers only part of the target ([#1154]).
- The daemon spawned by `start-daemon.cjs` exits on stdin EOF, so it never
  stays up; it now says so instead of reporting "started" ([#1158]).
- A rare "database is locked" on concurrent first open of a non-WAL
  database ([#1164]).
- Git timeout follow-ups: per-path deadlines and the watcher baseline
  ([#1165]).
- Queen follow-ups: a late `onComplete` can settle twice, and work stealing
  rarely runs under the slot cap ([#1153]).
- Learning outcome follow-ups: failures can still mint patterns, and
  routing still uses completion-based success ([#1147]).
- Pattern consolidation follow-ups: id-only read-back and no
  compare-and-delete ([#1149]).

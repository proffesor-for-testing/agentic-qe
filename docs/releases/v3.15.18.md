# v3.15.18 Release Notes

**Release Date:** 2026-11-01

## Highlights

AQE no longer fails with "database is locked" when several processes open a
new database at once, and cloud sync reads a `memory.db` that is not in WAL
mode without changing it. Git timeouts and failures are no longer reported
as "no changes", and predictions built on them report lower confidence.
`aqe coverage` says why it refused a coverage report instead of reading a
file outside the project or hanging on a FIFO. Learned patterns are moved
and merged safely, re-seeding no longer duplicates them, and a recreated
`memory.db` can no longer overwrite a richer brain checkpoint.

## Fixed

- **Concurrent first open of a database** ([#1164], [#1319]): when the MCP
  server, hooks and the CLI opened a database that was not yet in WAL mode
  at the same moment, about 1 in 20 opens failed with "database is locked".
  The switch to WAL is now retried within the busy timeout. With
  `AQE_DISABLE_WAL` set, AQE no longer switches the database back to WAL.
- **Cloud sync reads a non-WAL `memory.db`** ([#1320], [#1324]): `aqe sync`
  and `aqe sync status` opened the database read-only and then tried to
  switch it to WAL, so every SQLite source was skipped with "attempt to
  write a readonly database". The reader now leaves the file's journal mode
  unchanged and reads DELETE-mode and WAL-mode databases alike.
- **Git timeouts are not "no changes"** ([#1165], [#1327]): a git timeout,
  output overflow or failed git call no longer reads as an empty history or
  an empty change set, and nothing is cached from it. The quality daemon's
  git watcher retries a timed-out diff instead of skipping the commit.
  Overlapping defect predictions on the same file each keep their own
  deadline and warning.
- **`aqe coverage` says why a report was refused** ([#1186], [#1335]): a
  coverage report symlinked out of the project, a FIFO or device, or a file
  over the size limit is named with the reason in `aqe coverage`,
  `aqe fleet run analyze` and MCP `coverage_analyze_sublinear`. Before,
  `aqe coverage` read a `coverage-final.json` symlinked out of the project
  and reported it as measured coverage, and hung on a FIFO. Hardlink
  refusal is tracked in [#1329] and the remaining unconfined reader in
  [#1337].
- **Cross-domain pattern seeding is idempotent** ([#1325], [#1334]): if
  the "already seeded" flag was lost while the patterns remained, each
  session copied patterns again, including copies of copies, and the
  pattern table kept growing. A re-run now adds nothing. Cleanup of
  duplicates left by earlier versions is tracked in [#1332].
- **Pattern archive moves and merges** ([#1149], [#1314]): a pattern is
  deleted only after its archive copy is read back in full and matches.
  A usage update made during a move is kept, and a merge that fails part
  way is rolled back or reports exactly which sources were removed.
- **A recreated `memory.db` no longer overwrites a richer brain
  checkpoint** ([#1251], [#1316]): the end-of-turn hook keeps the existing
  `.agentic-qe/aqe.rvf` if a table collapsed, logs why once and backs off.
  Routine retention, `aqe learning prune --apply` and dream retention are
  still checkpointed. A global `aqe` too old for the new export options
  keeps the checkpoint and says to upgrade.
- **Defect prediction history** ([#1137], [#1315]): pruning no longer
  deletes runs it cannot parse, the latest run for every target is kept,
  and a stored run is not reported as failed when only cleanup failed. The
  background worker reports health as unmeasured, not 100, when it
  measured nothing.
- **First start after upgrading with float noise** ([#1302], [#1317]): a
  project's embedding space created before 3.15.17 is kept, after checking
  that the current embedder reproduces stored vectors, instead of being
  split into a new space.
- **Learning outcomes** ([#1147], [#1321]): failed runs no longer create
  learned patterns, a domain whose runs all failed is no longer listed as
  top performing, and `learn` says why it learned nothing. A test file
  that does not exist is reported as a caller error, not a failed test.

## Changed

- **`aqe coverage` exit code for a refused report** ([#1335]): when the
  coverage report is refused, `aqe coverage` exits **3** and labels the
  figures UNMEASURED (a static estimate, no threshold verdict). Before, it
  exited 0. Scripts that treated exit 0 as "coverage measured" now see the
  failure.
- **Defect prediction confidence after a git timeout** ([#1327]): a
  prediction for a file whose git history timed out reports half its
  confidence share (0.375 instead of 0.75 for a single file), together
  with the timeout warning.
- **Domain-filtered pattern search with an empty query** ([#1334]): the RVF
  pattern store now filters by domain in SQL, so it returns the domain's
  patterns up to the limit. Before, it filtered the top rows of the whole
  table and could miss most of a domain.
- **Review and writing skills** ([#1312]): `brutal-honesty-review`,
  `sherlock-review` and `code-review-quality` no longer require a minimum
  number of findings. A clean change can get a clean verdict, and the
  `brutal-honesty-review` output schema now requires an `evidence` field
  for each finding. `sherlock-review` adds an `UNVERIFIED` verdict.
  `technical-writing` and `agentic-quality-engineering` no longer contain
  invented statistics, and agent names in those skills use the current v3
  names (for example `qe-test-architect` instead of `qe-test-generator`).
  These skills are installed by `aqe init`.
- **Dev dependencies** ([#1308], [#1311]): lockfile updates for `qs`,
  `body-parser`, `ip-address` and `protobufjs` resolve `npm audit`
  advisories. All are dev-only; the published package was not affected.
  The remaining dev-only findings are tracked in [#1310].

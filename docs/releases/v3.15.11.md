# v3.15.11 Release Notes

**Release Date:** 2026-10-22

## Highlights

AQE now works on npm 12 and on a plain install without the optional
embedding package, and its MCP tools load in VS Code Copilot. When the
database cannot start, `aqe init` prints the real cause and the command that
fixes it. `aqe fleet run` progress output is readable, a test that passes on
retry counts as passed and flaky, and an `eval()` is no longer reported twice.
Four security fixes close the follow-ups from the 3.15.10 review: a checked
file is read from exactly what was checked, runner stderr is redacted before
it is cut, and names like `constructor` or `__proto__` are plain names in
every data lookup.

## Fixed

- **`aqe init` explains a missing database driver** ([#1173], [#1175]): on
  npm 12, `npm install -g agentic-qe` blocks the install script of
  `better-sqlite3`, so its native binary is never built. `aqe init` then
  failed at "Initialize persistence database" with no error printed. Now
  `init` prints the real error, and every command that opens the database
  (`init`, `health`, `status`, `memory`, MCP fleet init) names the cause and
  prints the exact fix:
  `npm install -g agentic-qe --allow-scripts=agentic-qe,better-sqlite3,hnswlib-node`.
  The README and getting-started guide include the npm 12 install note.
- **MCP tools load in VS Code Copilot** ([#1185], [#1193]): Copilot refused
  `fleet_init` and 17 other tools with "tool parameters array type must have
  items". Every list parameter in every tool schema now declares what its
  elements are, including the `qe/*` domain tools, whose element types were
  dropped when they were published.
- **`task_orchestrate` and `aqe eval` work without an embedder** ([#1022],
  [#1181]): on a plain install without `@huggingface/transformers`,
  `task_orchestrate` always failed with "Transformer initialization
  previously failed" and `aqe eval` failed to load. Both now work. Pattern
  learning stores patterns without a vector and searches them by text; its
  response says so in a new `learning` field (`patternSearch: "vector"`,
  `"lexical-only"` with the reason, or `"unavailable"`). Text matches report
  `similarity: 0` because no similarity was measured. Experience guidance is
  not produced without an embedding of the task, instead of guidance for an
  unrelated task with a made-up similarity.
- **`aqe fleet run` progress output** ([#1168], [#1177]): the progress header
  shows `Fleet Progress` instead of a literal `{name}` and a stray `0`. When
  the verdict is FAILED, the completion line no longer says "successfully".
- **A test that passes on retry counts as passed and flaky** ([#1170],
  [#1177]): MCP `test_execute_parallel` and `aqe test execute` (text, JSON and
  markdown) now count it as passed, report it as flaky, and agree with
  `retryStats`. MCP and the CLI share one default retry count, 2 (MCP used 3).
- **`sast-scan` runs without naming a domain** ([#1170], [#1177]):
  `task_submit` and `aqe task submit` route it to `security-compliance`. A
  task type no loaded domain handles is still rejected, with an error that
  says so.
- **One `eval()` is reported once** ([#1170], [#1177], [#1184]):
  `security_scan_comprehensive` dropped a duplicate generic eval/exec finding
  only when SAST reported eval injection (CWE-95) on the same file and line,
  at the same or a higher severity, and the line has no `exec()`. Secret, CORS
  and debug findings are always kept. The generic rule reports every matching
  line, and its findings name the scanned path.
- **Learning recommendations stay in their domain and objective** ([#1091],
  thanks @rudycelekli): a strategy tuned to maximize coverage can no longer
  be recommended for minimizing latency or for another domain.
- **CRDT sync rejects non-finite timestamps** ([#1087], thanks
  @rudycelekli): a remote register with a `NaN` or infinite timestamp is
  skipped at merge instead of winning every later comparison; valid
  registers, including cleared ones, keep converging.

## Security

- **A checked file is read from exactly what was checked** ([#1161],
  [#1179]): the path guard checked a path, and the handler opened it again
  later by name, so a file or symlink swapped in between was read
  unchecked. Fixed-name files inside an accepted folder (coverage reports,
  `package.json`, dependency manifests) were not checked at all, so a
  committed symlink could pull an outside file into results or point a
  coverage report at `/dev/zero`. One shared reader now opens the file once
  without following a final symlink, checks the open file (regular, within the
  size limit, inside the project) and reads from it. Code index, SAST,
  security scans, contract and requirements validation, test generation, C4
  and every coverage report parser use it.
- **Test runner stderr is redacted before it is cut** ([#1150], [#1180]):
  when coverage tests crashed without a report, `coverage_analyze_sublinear`
  quoted the runner's raw stderr, and a secret cut at the 2 KB boundary left a
  fragment no redaction pattern recognizes. Stderr is now redacted first, then
  cut. Claim-verifier command evidence and the claude-code provider's parse
  error are redacted the same way.
- **`constructor`, `__proto__` and other built-in names are plain names**
  ([#1157], [#1182]): names from callers, files or stored data matched
  built-in JavaScript members. A pipeline condition on `input.constructor`
  ran a step that should be skipped, a dependency named `constructor` crashed
  `qe/code/c4` and hid real findings, an agent-overlay `__proto__:` section
  wrote onto every object, and a tool named `constructor` could claim to be
  read-only. Every such lookup now reads own entries only.

# v3.14.7 Release Notes

**Release Date:** 2026-10-02

## Highlights

This patch makes browser setup opt-in, so installing AQE no longer downloads
Chrome. The MCP server now always shuts down cleanly: it releases its pattern
store lock and closes the learning database however it is stopped. Pattern
search uses keyword and vector matching together, with a keyword index that
repairs itself. Test generation can build real assertions from examples you
supply, and no longer guesses expected values.

## Changed

- **Browser setup is now opt-in.** `npm install agentic-qe` and `aqe init` no
  longer install Vibium or download a browser. Run
  `aqe init --browser-engine` when you need browser-based testing (visual,
  accessibility, e2e). Vibium 26.8.21 is now an optional peer dependency, and
  `--no-browser-engine` skips browser setup explicitly. Existing installs are
  not affected ([#797], [#812]).
- **Test generation no longer guesses expected values.** Without examples and
  without an LLM, `test_generate_enhanced` and `aqe test generate` produce a
  clearly marked, skipped scaffold instead of generic assertions such as
  `toBeDefined()`. The coverage estimate is reported as unmeasured rather than
  as an invented percentage ([#795]).
- `aqe test generate` now exits with code 1 when generation is rejected, for
  example when an example names a function the file doesn't export. CI scripts
  can rely on the exit code ([#811]).
- Pattern search for routing and `task_orchestrate` uses keyword (FTS5) and
  vector matching together. Pattern hints now report `similarity`, `score`,
  `matchType` and `canReuse`, so you can see why a pattern matched. An
  experience reinforces an existing pattern only when it describes the same
  task, so unrelated tasks no longer strengthen each other's patterns ([#796]).

## Added

- Behavior examples for test generation: pass `behaviorExamples` to
  `test_generate_enhanced`, or `--behavior-examples <file>` to
  `aqe test generate`. Each example gives a function, its arguments and the
  expected result. The generated assertions come only from those examples
  (Vitest, Jest and Node's test runner). See
  `docs/test-generation/deterministic-examples.md` ([#795]).
- The task audit log reports whether its retained window is complete or
  truncated, with recorded, retained and dropped counts, through the new
  `getSnapshot()` and in `getStatistics()` ([#803]).

## Fixed

- The MCP server releases `patterns.rvf.lock` and closes the learning database
  cleanly on every kind of shutdown: input stream closed, JSON-RPC `shutdown`,
  SIGTERM/SIGINT, and the shutdown watchdog. This holds for both `aqe-mcp` and
  `aqe mcp`. Previously the lock was left behind, so the next start had to
  recover a stale lock, and the database's write-ahead log was not
  checkpointed ([#802], [#808]).
- The learning database repairs its keyword search index when it opens.
  Databases whose sync triggers had gone missing kept a stale index: patterns
  added later were invisible to keyword search, and deleted ones still matched.
  The repair recreates the triggers and rebuilds the index without changing
  any stored patterns. Read-only opens are skipped ([#809]).
- Invalid behavior examples are rejected with a clear error before any work
  starts, and no longer trip the test-generation circuit breaker. Previously
  two bad requests could block test generation for everyone on that MCP
  server for about 30 seconds ([#795]).
- Updated `brace-expansion` and `@grpc/grpc-js` in the development dependency
  tree ([#806]).

## 3.15.2 — 2026-10-10
- fix: aqe-mod `status.json` reports the plugin version as `modVersion`, not a hard-coded `0.1.0` (#923). `hooks/version.ts` is generated by `scripts/sync-plugin-versions.cjs` (the npm `version` hook), and `--check`, `smoke.sh` and `smoke-mod.sh` fail on drift.
- fix: aqe-mod guard counts and the last refusal survive the session that made them (#924). `status.json` adds `totals: {calls, blocked, flagged, since}` across sessions, and `lastRefusal: {atMs, tool, outcome, reason}` with the reason cut to 200 characters and never the command. The per-session counters are unchanged, and the file stays `version: 1`. A missing or corrupt file starts the totals from zero and never affects a tool call. Sessions running side by side add to the totals instead of overwriting them.
- feat: `/aqe-mod status` shows `this session:`, `all sessions:` and the last refusal (time, tool, outcome, reason).
- fix: aqe-mod status file: never follow symlinks. The mod checks `.claude-flow`, `.claude-flow/aqe-mod` and `status.json` with `$.fs.stat` before every read and write. If any of them is a symbolic link or not a folder or regular file, it neither reads nor writes the file, and `/aqe-mod status` says why.
- fix: aqe-mod status file contents are validated when read back. Times past now plus one day are dropped, and `/aqe-mod status` prints `unknown` for a time it cannot show. A last refusal whose reason is not the guard's is dropped. Stored reasons keep the verb and only the `.agentic-qe/...` part of a path (otherwise `<path>`).
- chore: `sync-plugin-versions.cjs --check` names `hooks/version.ts` and what it expected when that file drifts or was edited by hand.

## 3.15.1 — 2026-10-10
- fix: aqe-mod guard now refuses the bypasses that the post-merge adversarial review of 3.15.0 confirmed: shell keywords before the verb (`then rm`, `do rm`, `! rm`), brace expansion (`memory.db{,-wal,-shm}`), interpreter one-liners with several arguments and the destructive APIs they missed (`fs.rm`, `rename`, `copyFile`, `open(..., 'w')`, `os.replace`, pathlib, Perl/Ruby/PHP/Deno/Bun), `cd .agentic-qe && rm ./memory.db`, combined shell flags (`bash -lc`, `sh -ec`, `zsh -c`), git global options (`git -C . clean -fdx`, `git -C .agentic-qe rm`), `git clean -e` excludes that do not keep the data, sqlite3 `.backup`/`.save`/`.output`/`.once` onto a store, `ALTER TABLE ... DROP`, `$(pwd)/.agentic-qe/...`, and `find . -name '*.db' -delete` from the project root
- fix: aqe-mod guard refuses what a second adversarial review found: `find` deleting `.agentic-qe` by name or path (`find . -name .agentic-qe -exec rm -rf {} +`, `-path "*agentic*" -delete`), `find ... | xargs rm`, `rimraf`/`del`/`trash`, ANSI-C quoting (`rm $'\x2eagentic-qe/memory.db'`), substitutions nested past the reader's depth, `sqlite3 "file:...?mode=rw"`, `DELETE/**/FROM`, quoted identifiers hiding a literal, `coproc NAME { rm ...; }`, and directory restores into `.agentic-qe` (`cp -r backup/.agentic-qe ./`, `rsync -a backup/ .agentic-qe/`)
- fix: aqe-mod guard refuses when it cannot prove the store is untouched (third review): unresolved `$NAME`/`${...}`/`$@`/`$(...)` in a path read as `*` and `${X:-w}` as `w` or `*`; `find` exclusions count only in exact `-prune -o` / `-not -path '.../*'` forms without `-depth`; every `-exec` is read past wrappers (`-exec sudo rm`, `-exec git rm`); POSIX bracket classes, `[!]x]`, extglob and `shopt -s dotglob` globs; `$"..."`, braces in partly quoted words, `busybox rm`, `find ..`/`~`/`"$HOME"`, here-strings into `xargs`, `parallel rm`
- fix: aqe-mod guard reads command substitutions by what they may print (fourth review): `$(find ...)`, `$(ls -A)`, `$(git ls-files -o)` and opaque producers (`$(cat list)`, `base64 -d`) may yield the store, in arguments, `DB=$(...)` bindings, `for f in $(...)`, `< <(...)` feeding `read` and `... | xargs rm`; `bash -c`/`eval` of a wholly unknown script is refused
- fix: aqe-mod guard reads PowerShell pipelines (`gci .agentic-qe *.db | ri`, recursive listings piped into Remove-Item), `iex`/`Invoke-Expression`, `& { ... }`, `Start-Process -ArgumentList` and `New-Item -Force`
- fix: aqe-mod guard: `-prune` never counts with `-delete` (BSD `-d`), and exclusions count only as exact conjuncts; `find -exec` is judged by its verb (so `-exec grep -l rm {}` and `-exec cp {} /tmp/backup/` pass), with `git rm`, `sh -c` text and SQLite clients judged on what they do; UPDATE, `.read`, `sqlite3 db < file`, unterminated heredocs, `VACUUM INTO`, `sqlite-utils`, `litecli`, `sponge`, `awk -i inplace`, `tar -x -C`/`unzip -d` into `.agentic-qe`, `rimraf@5`, `shx rm`, `pnpm exec`, and `cd $(...)` to an unresolved directory are refused; values longer than 4 KiB are read as `*`
- fix: aqe-mod guard (fifth review): a substitution's or pipeline's `find` is judged on everything it prints (`$(find . -name '*.db' -o -name '*.tmp')`); arrays, `mapfile`/`readarray` and `${arr[@]}` carry what a substitution may yield; `git status` and `$(< file)` may print the store; an unknown prefix may be empty (`"$X.agentic-qe"`); bracket globs stay whole in substitutions (`$(echo .[a-z]*)`); only a literal `find -path` narrows; PowerShell variables, splats, `foreach`, `.Delete()`, `-Force`/`-Hidden` listings, `sl .agentic-qe`, `pwsh -c`, `Start-Process` comma lists and `wsl` are read; `which`, `command -v`, `npm config get cache` and similar tool paths pass
- fix: aqe-mod guard (sixth review): prefix assignments bind for `bash -c` (`D=.agentic-qe bash -c 'rm -rf $D'`, a regression since 6c8d8187); `+=` appends; array slices; here-strings and the expanded words of earlier pipeline stages feed `read`, `mapfile` and `xargs`; PowerShell `+=`, `(...)` arguments, `$var.Delete()`/`.MoveTo()` and `-OutVariable`; a `Where-Object` filter narrows a PowerShell feed only as a pure conjunction with a positive literal `-eq`/`-like` on Name or Extension that cannot match a store file (so `... | Where-Object Extension -eq '.tmp' | Remove-Item` passes, and `-or`/`-not` filters do not); `done <<< "$dbs"` feeds `while read` after `dbs=$(find ...)`
- fix: aqe-mod guard cost is bounded: globs are matched linearly (20 or 200 `*` no longer hang), the reader is linear in pipelines and redirects, commands over 256 KiB are refused unread, and a guard that threw or overran refuses the call without judging it again; variable expansion has a 256-result budget per word, brace expansion is linear with length/depth caps, and script literals are scanned linearly (every review bomb is judged in under 50 ms)
- feat: aqe-mod guard also reads Monitor and PowerShell tool commands (`Remove-Item`, `Move-Item`, `Set-Content`, `Out-File`, .NET file APIs, `cmd /c del`)
- fix: aqe-mod guard no longer refuses read-only lines that mention SQL or code words elsewhere (`ls .agentic-qe && grep -rn "DROP TABLE" src/`). SQL is checked only in `sqlite3` commands (`-readonly` exempt, string literals ignored), and code only in interpreter commands
- fix: aqe-mod guard allows backup-named copies next to the store (`.agentic-qe/memory-backup-20261009.db`) and script copies *from* the store (`shutil.copy('.agentic-qe/memory.db', '/tmp/x.db')`); every `.agentic-qe` stays protected, temp-directory fixtures included
- chore: aqe-mod guard split into focused modules (`shell.ts`, `braces.ts`, `glob.ts`, `context.ts`, `commands.ts`, `find.ts`, `verbs.ts`, `scripts.ts`, `powershell.ts`); the `.catch` fail-closed decision is the pure `fallbackVerdict`, now tested with notify mode; the attack/benign corpus grows from 95 to 525 cases (393 attacks, 132 benign); timing tests take the median of 5 runs against a 250 ms bound, plus timing tests on pathological inputs
- docs: README "As a mod" records the guard's decisions (restore flow and temp-fixture cleanup refused in enforce, `UPDATE` refused, `git clean -e`, size limits) and its limits
